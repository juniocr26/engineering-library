# Read-only documentation validator

Run from the parent workspace (Python 3.10+; standard library only):

```sh
python3 -B engineering-library/tools/check_docs.py --workspace .
python3 -B -m unittest discover -s engineering-library/tools -p 'test_check_docs.py' -v
```

From the library, the default workspace is the script's parent workspace; use `python3 -B tools/check_docs.py`. Output is structured JSON on stdout, with repository/document inventory, severity/code/path/detail findings and limits. Exit 1 means validation errors, exit 0 means none; warnings/info remain visible. The caller may redirect stdout to a report file. The validator itself performs no writes, network calls, application execution or credential/data reads. Isolated tests create temporary synthetic documentation trees and run only this validator.

`--config PATH` selects safe workspace `tools/*.json` metadata; default is `tools/docs_manifest.json`. The manifest defines `repositories`, `required_documents`, optional `exceptions` (per-repository relative paths) plus `exception_reasons`, and optional `additional_categories` with reasons. Repository names are immediate safe directory names. Discovery considers immediate directories with a Git marker; unexpected repositories are errors so the completion inventory cannot silently omit new work. `inventory_before` preserves the original document list but is informational, not a set of obsolete paths to require. No private workspace names are hardcoded in Python. The current manifest configures this portfolio explicitly.

The scan reads only repository READMEs and `.md` under docs/en and docs/pt-BR. Categories (including unknown/empty directories), indexes/checklists, language counterparts, local targets/anchors, index reachability, retained numbered interview sections, added Q001 sequences, explicit answers/follow-ups, obsolete local library names and private-key markers are checked. New-question parity checks IDs, not translation quality. Existing answers were preserved and reviewed separately; structural checks cannot assess depth or technical truth.

Before normalizing a local link, lexical components are checked for restricted directories/files. Links to real environment files, private keys, application storage, dependencies, Git internals or outside the workspace are classified without reading targets. Symlink components are rejected with lstat; symlink directories are never traversed. Safe non-document links get existence/type checks only, not content reads. Anchors are checked only against maintained Markdown already loaded. Unreadable/invalid UTF-8 documents become findings. Findings never echo a detected private-key body. There is a TOCTOU window between lstat and reading in a maliciously changing filesystem; this is a cooperative local documentation checker, not a race-free security sandbox.

Parser support is a deliberate subset: ATX/Setext headings, common Unicode slugs and duplicate suffixes, simple inline links/images, full/collapsed reference links, defined shortcut targets, percent-decoded local URLs, explicit HTML id/name anchors, and exclusion of fenced/inline code. Complex nested brackets/parentheses, multiline destinations, full HTML/MDX, all escaped/entity slug rules and complete GitHub renderer equivalence are not guaranteed. Missing undefined shortcut references may not be recognized. Review complex syntax manually. External links are neither fetched nor marked verified. The JSON report retains those limits rather than claiming full Markdown compatibility.

The [completion report](../operations/workspace-completion.md) records the actual final result. [Isolated tests](../../../tools/test_check_docs.py) include valid/read-only fixtures, missing repositories/counterparts, broken links/anchors/references, Unicode/encoded paths, reachability/categories, restricted traversal, symlinks, metadata-only source links, unreadable inputs, interview alignment, exceptions, private-key/name findings, fence handling, empty/unknown categories, retained-number gaps, symbolic workspace rejection and CLI exit/JSON behavior.

## 2026-10-18 tooling update

The JSON `summary` contains repository/document/error/warning counts and finding codes. `external_links` explicitly reports occurrences as `not checked`; no URL is fetched. `scope_exclusions` maps documented non-project scope patterns to nonempty reasons; it never suppresses an unexpected Git repository. Symbolic Git markers are not followed. Private `.local-backups` links are blocked before reads. Config must be a regular safe tools/*.json file; FIFO configuration is rejected without opening it. Four additional isolated tests cover these cases, including a read guard, unexpected-repository behavior and nonregular input timeout. Parser and semantic-review limits above remain unchanged.
