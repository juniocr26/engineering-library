# Architecture and integration boundaries

## Server architecture — 2026-11-16

Server deployment combines the base Compose configuration with its server overlay and uses externally managed Redis. The overlay removes the local `redis` service and its database-only mount; application dependencies and manager endpoints are adjusted. The application builds from `docker/Dockerfile.server`, reusing existing runtime clients and entrypoints. Development retains its original local database service and persistence. Removing a mount from configuration is not migration or physical deletion of existing data.

## Verified state and public boundaries — 2026-11-11

Node.js ES modules service using Socket.IO, Redis and jose. Redis publishing/subscription connections and readiness are separate from publisher/recipient authorization. RabbitMQ serves application consumers without installing a PHP library in Hub. Redis Pub/Sub and live output do not provide durable replay. Node logs, RabbitMQ messages, delivered events and TracePaw events generated by Laravel consumers are distinct evidence.

Source inspection and local metadata do not confirm Docker image contents, deployment, mounts or external acceptance. This public summary omits internal endpoints, topology, identifiers and private rules; full operational contracts remain in source repositories. No database catalog synchronization was performed.
