`caught_exception_identifiers` traverses the selected function’s lexical AST subtree and collects bounded static names from catch clauses. It can record simple names, attribute chains and direct tuple elements. It does not resolve exception classes or establish which nested body executes. Bare catches and dynamic type expressions do not become resolved class facts. [source:E5]

`quoted_caught_identifier_mismatch?` activates for a backticked source catch identifier and requires its admitted spelling in both language explanations. A source-qualified spelling and its terminal name can agree when unambiguous. Distinct qualified names sharing a terminal require the same named reference sets across languages; an unsupported owner is refused. [source:E3] [source:E4]

This refusal is conditional on AST metadata being present in the card. It is not a general validator for prose without quoted source identifiers, code keys, all exception expressions, execution order or factual equivalence. Citation integrity, identifier preservation and full semantic review are separate obligations. [source:E1] [source:E3] [source:E4] [source:E5]
