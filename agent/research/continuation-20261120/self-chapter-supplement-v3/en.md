`caught_exception_identifiers` traverses the selected function’s lexical AST subtree and collects bounded static names from catch clauses. It can record simple names, attribute chains and direct tuple elements. It does not resolve exception classes or establish which nested body executes. Bare catches and dynamic type expressions do not become resolved class facts. [source:E5]

`quoted_caught_identifier_mismatch?` activates for a backticked source catch identifier and requires its admitted spelling in both language explanations. A source-qualified spelling and its terminal name can agree when unambiguous. Distinct qualified names sharing a terminal require the same named reference sets across languages; an unsupported owner is refused. [source:E3] [source:E4] [source:E12]

These refusals require supported AST metadata in the card. They do not certify map-pair direction, reference roles, arbitrary new identifiers, every code key, nested or mixed dictionaries, runtime bindings, execution order or full EN/PT factual equivalence. The shared helper checks source-reference presence in the explanation; it is not a complete semantic parser of every code span. Citation integrity, reference preservation and semantic review remain separate obligations. [source:E1] [source:E3] [source:E4] [source:E5]

`direct_return_mapping_identifiers` records bounded ASCII name/attribute references when direct return statements contain literal dictionaries made entirely from those references. The profile permits up to 32 pairs and 64 unique references; unpacked, mixed, nested-only and oversized maps are outside its coverage. It records lexical spelling rather than resolved class identities or an executed return value. [source:E5]

`quoted_return_mapping_identifier_mismatch?` sends the known map references to `quoted_identifier_reference_mismatch?`; the existing catch-reference entry uses the same helper. A backticked known reference triggers a cross-language presence/allowed-owner check. When distinct source spellings share a terminal, both explanations must preserve the same named-reference set. This does not verify which reference is the dictionary key or value. [source:E3] [source:E4] [source:E12] [source:E13]

HelperRetrieval `validate_unit` now reconstructs the expected selected Python unit with `python_unit`, and the selected Go unit with `extract`, before comparing canonical evidence. The comparison also binds admitted declaration metadata and Go producer fields; it is not runtime symbol or upstream Git authentication. [source:E14] [source:E15] [source:E16] [source:E18]
